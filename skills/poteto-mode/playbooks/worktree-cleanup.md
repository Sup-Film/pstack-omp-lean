### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then run the bundled `worktree-audit.sh [-b <pr-base-ref>] [repo-path]` (`skill://poteto-mode/scripts/worktree-audit.sh`) (principle-build-the-lever). Resolve `$SKILLDIR` per the Bundled scripts section of `skill://poteto-mode`, then run `"$SKILLDIR/scripts/worktree-audit.sh" [-b <pr-base-ref>] [repo-path]`. Without `-b` it checks `MERGED` against `origin/HEAD`, so pass `-b origin/<branch>` when PRs target another branch. It reads paths from `git worktree list`, never hand-typed, since a hand-typed conventional path can miss a worktree created elsewhere by the active host (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, lock state, and PR state, then suggests a bucket.
2. The bucket is advice, not permission. The pinned and active sessions are the real artifact (principle-prove-it-works). Get that set from the user and from the root's recorded `agent://<id>` sessions, and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `review` row, or anything you doubt, fan explorer **Bounded sessions** out through the active adapter to read the matching workspace's `history://<id>` transcripts and report whether the session is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned session spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never appear in a session list. Treat missing history as unknown, never as proof of inactivity. Pick each subagent's agent and effort for the job, per the Delegation section.
4. Pause on irreversible loss or protection. `wip:N` is N tracked uncommitted edits. `scratch:N` is N untracked files, not proof they are disposable. Show every changed and untracked file and get a decision before removing either kind, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `locked:<reason>` is an intentional Git protection and always holds, and a lock needs a separate explicit unlock decision. An `INSPECT` value other than `ok` means the audit could not read the worktree, so hold it. Per Autonomy, clean, unlocked, merged, and proven not-in-use proceeds. The `hold-wip`, `hold-scratch`, `hold-locked`, `hold-open-pr`, and `hold-error` buckets, and anything in use, pause.
5. Prune the confirmed set recoverably. Move each approved worktree directory to Trash with `trash <path>` (the `trash` CLI must be installed), then run `git worktree prune`. Do not run `git worktree remove --force`, which can destroy untracked files before Trash sees them. Branch refs survive, and the trashed directory remains recoverable until Trash is emptied. Trash is recoverable staging on the same filesystem, so it reclaims no space by itself: report reclamation as whatever the real `df -h /` delta shows, and treat permanently emptying Trash as a separate authorized step. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`; package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in use by which session, locked, or uncommitted work).
